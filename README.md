# Daymark

Daymark 是一个本地优先的桌面日程待办工具。它把「随手收集 → 安排到今天 → 完成并记录成果 → 生成月度/季度/年度总结」连成一个简单闭环。无需账号，任务、日志和本地报告默认只保存在本机；只有用户主动点击 AI 总结并确认发送时，勾选范围内的数据才会提交给 OpenAI。

## 已实现功能

### 任务与每日计划

- 收件箱、今天、即将安排、全部待办、已完成五个视图
- 计划日期与最后期限分开：两者同时设置时形成自动规划区间；最后期限不能早于计划日期
- 跨期任务按照中国工作日、调休安排、预计用时和每日剩余容量自动拆分，容量不足时提示超载
- 没有预计用时的跨期任务仍显示完整日期范围，并在可安排工作日提示“待估时”
- 今天、明天、提醒、完成归属和工作报告统一采用中国标准时间（Asia/Shanghai，UTC+8）
- 今日 Top 3、预计用时、每日可用容量和超载提示
- 晨间“规划今天”：按昨日未完成、到期风险、逾期和近期收件箱给出候选，确认后才会改动日期或 Top3
- “今天”按 Top3、今天安排、逾期延续和其他事项分组，并解释每项为何出现在今天
- 下班“今日收尾”：逐项完成、顺延、指定日期、移回收件箱、保持原计划或记录阻塞，同时沉淀今日成果与明日重点
- Top 3 任务在待办列表、已完成列表和日历回顾中均显示明确的“★ Top 3”标签
- 可为任意任务添加不受数量限制的普通旗标；列表支持一键添加/移除，详情和回顾同步显示“⚑ 旗标”
- 工作领域、优先级、备注、完成说明和来源链接
- 实时搜索、删除/修改/完成撤销，以及键盘操作
- 每天、工作日、每周、每月重复任务；月末重复会保留原始日期锚点
- “工作日”重复以中国工作日历为准：跳过法定假日，并会落在调休上班的周六
- 本机通知提醒；重复任务会按新日期顺延提醒
- 默认按中国时间 17:30 提醒当天仍未完成的事项；时间可调整或关闭，每天最多提醒一次，点击通知直接进入今日收尾，收尾后当天不再提醒

### 工作记录与总结

- 自动沉淀不可变的操作日志；用户可见回顾按照任务当前归属和实际完成日期动态重建
- 今日备注可补充成果、阻塞和上下文
- 42 格完整月历，可浏览过去和未来月份，并展开某一天的跨期阶段、自动分配用时、完成情况和工作备注
- 未完成任务只出现在当前有效的计划日期或规划区间；改期会从旧日期移除，移回收件箱会撤回全部日历安排
- 已完成任务只归属于中国时间对应的实际完成日期；同一个跨期任务在季度和年度报告中只计算一次
- 标注国务院发布的 2026 年法定节假日与调休上班日，并展示数据来源
- 休息日标注以国务院发布的工作日历为准，而不是单纯看星期几：调休上班的周六只显示“班”，不会被当成休息日；法定假日即使落在工作日也会标注
- 计划在休息日的任务会在待办列表、每日回顾和执行时间块中显示“周末安排”或“假日安排”标签
- 节假日与调休数据只维护一份（`src/china-calendar.js`），自动排程和日历显示共用，不会出现两者判断不一致
- 按月、季度或年度生成确定性的本地工作总结，包括活跃天数、计划/完成数量、完成率、Top 3、高优先级成果、工作领域、趋势、长期延续事项和每日备注
- 成果说明会优先进入总结；同一成果不会在合并展示中重复出现
- 可选使用 OpenAI 生成更适合汇报的 AI 初稿；切换范围或取消时不会让旧请求覆盖新报告
- 本地报告和 AI 初稿均可继续编辑，并一键复制 Markdown 或保存为 `.md` 文件
- 在“已完成”中补录用时或完成说明会同步到对应完成日；删除事项会同时从日历、回顾统计和 AI 数据源中移除
- 将误完成的任务恢复为待办后，会同步撤销日历、回顾统计和 AI 总结中的完成结果
- “已完成”按中国时间的完成日期分组，组内按完成时间倒序排列；恢复或删除后分组即时更新
- “执行日历”提供可独立滚动的日/周 24 小时时间轴；自动排程为虚线，拖动或拉伸后转为手动锁定的实线时间块
- 可开始/暂停专注计时，也可手动补录多段实际用时；任务列表、每日回顾和周期报告统一显示实际投入
- 期限风险会比较剩余预计工作量与截止日前可用容量，提前提示无法按期完成的事项

### AI 与隐私

- AI 是可选能力：不配置 API Key 时，待办、日历和本地总结全部可正常使用
- API Key 由 Electron `safeStorage` 加密后单独保存；明文不会写入待办数据、导出文件、渲染进程或日志
- 每次生成前都会显示发送范围并要求确认；任务标题、领域和汇总指标会发送，来源链接、提醒、删除记录、事件历史和私密备注不会发送
- “完成说明”默认勾选，“每日备注”默认关闭，可在每次生成前单独控制
- 请求固定发往 OpenAI 官方 Responses API，使用 `store: false`；AI 草稿只保留在当前应用内存中，除非用户主动保存
- 设置页只显示是否已配置密钥，不会把已保存的密钥回传给界面

### 本地数据与可靠性

- JSON 原子写入、上一个有效版本备份、损坏文件保留与自动恢复
- 旧版 v1 数据首次加载时自动迁移到带事件历史的数据结构，并永久保留迁移前备份
- v2 数据首次加载时自动升级到支持排程块和多段用时的 v3，并永久保留迁移前备份
- 首次升级到中国时间版本时，旧事件会按其绝对发生时间重新归入中国日期，派生日归档自动重建，原数据保留在 `.bak` 备份中
- 每次任务变化和设置变化都会写入带前后快照的审计事件，支持历史回放
- File 菜单可导出完整 JSON 备份或任务 CSV
- 新版本数据遇到旧客户端时会拒绝覆盖，避免向下兼容造成数据损坏

## 快捷操作

- `Cmd/Ctrl + N`：在当前窗口新建任务
- `Cmd/Ctrl + F`：搜索任务
- `Cmd/Ctrl + Z`：撤销最近操作（焦点不在输入框时）
- `Cmd/Ctrl + Shift + Space`：全局唤起 Daymark 并聚焦新建任务
- 任务列表中可用方向键选择，空格完成，Delete/Backspace 删除

## 安装与首次使用

1. 打开 `dist/Daymark-1.6.0-arm64.dmg`，将 Daymark 拖到“应用程序”。
2. 当前本机验收包没有 Apple Developer ID 公证；若首次启动被拦截，请在 Finder 中右键 Daymark 选择“打开”。
3. 日常待办、节假日日历和本地工作总结不需要 API Key。在“工作回顾”页配置自己的 OpenAI API Key 后，才会启用 AI 初稿。
4. 如需核对安装包完整性，请进入 `dist/` 后运行 `shasum -a 256 -c SHA256SUMS.txt`。

## 开发与验证

需要 Node.js 22.12 或更高版本。

```bash
npm install
npm start
```

运行领域、日历、报告、AI 边界、安全和持久化测试：

```bash
npm test
```

运行真实 Electron 端到端检查。该命令会使用隔离的临时数据目录，自动执行新建、规划、完成和季度报告流程：

```bash
npm run smoke
```

生成用于本机验收的临时应用（终端会打印系统临时目录）：

```bash
npm run pack
```

生成 DMG、ZIP 和 SHA-256 校验文件：

```bash
npm run dist
```

产物位于 `dist/`。当前交付包面向 Apple Silicon（arm64）Mac，使用 hardened runtime 和 ad-hoc 本地签名，未做 Developer ID 签名和 Apple 公证，适合本机验收。若系统拦截首次启动，可右键应用选择“打开”，或在“系统设置 → 隐私与安全性”中确认打开；若要公开分发，需要补充正式签名、公证和更新渠道。

## 数据位置

正式应用将数据保存到 Electron 的 `userData/daymark-data/todos.json`。在 macOS 默认通常是：

```text
~/Library/Application Support/Daymark/daymark-data/todos.json
```

同目录会按情况出现：

- `todos.json.bak`：上一个有效写入版本
- `todos.json.v1-backup.json`：首次 v1→v2 迁移前的永久备份
- `todos.json.v2-backup.json`：首次 v2→v3 迁移前的永久备份
- `todos.json.corrupt-<timestamp>.json`：检测到损坏时保留的原文件

AI 配置单独保存在：

```text
~/Library/Application Support/Daymark/daymark-data/ai-settings.json
```

该文件仅包含模型设置和经系统安全存储加密后的密钥密文，不会随 Todo JSON 或 CSV 导出。也可以不保存密钥，改用启动环境中的 `OPENAI_API_KEY`。

报告和手动导出的备份由用户自行选择保存位置。
